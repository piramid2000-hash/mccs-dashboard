# tag-audit — SEION 증거 태그 규율 검수

문서가 `CLAUDE.md`의 규율(증거 태그·금지 표현·고정 택소노미)을 지키는지 기계적으로 점검하고,
사람이 판단해야 할 부분만 남겨 보고한다.

## 언제 쓰나

- 레시피·계획서·보고서·대시보드를 **작성/수정한 직후, 게시 전**
- 외부에서 받은 덱·문서를 체계에 편입하기 전
- 사용자가 "태그 점검", "규율 검수", "과장 표현 확인"을 요청할 때

## 실행 절차

### 1단계 — 기계 검출

대상 파일에 스크립트를 실행한다. 인자를 주지 않으면 저장소 전체(`docs/`, `*.md`, `*.html`)를 훑는다.

```bash
python3 .claude/skills/tag-audit/scripts/audit.py <파일 또는 디렉터리>...
```

출력은 `파일:줄번호 [규칙ID] 내용` 형식이며, 규칙 ID는 아래와 같다.

| ID | 검출 대상 |
|---|---|
| `T1` | 태그 없는 성능·경제 수치 (%, V, mA/cm², kWh, 시간, $, 년 등) |
| `T2` | 금지 표현 (보장·완료·원천 차단·영구·무전력·100% 전환·0% 등) |
| `T3` | 전력 원단위(kWh/Nm³) 주장에 패러데이 검산 근거 부재 |
| `T4` | F1~F5 명칭이 표준 택소노미와 불일치 |
| `T5` | UT 번호가 UT-00~09 범위 밖이거나 미정의 |
| `T6` | 낙관 수치가 Base/Upside 구분 없이 단독 제시 (전압·일정·회수기간) |
| `T7` | soak/침지 시험만으로 안정성을 주장 (음극 분극 언급 부재) |

### 2단계 — 사람 판단 (스크립트가 하지 못하는 것)

기계 검출 결과를 그대로 보고하지 말고, 각 항목을 다음 기준으로 **분류**한 뒤 보고한다.

- **실제 위반** — 수정 필요. 구체적 수정안(어떤 태그를 붙일지, 어떤 표현으로 바꿀지)을 함께 제시.
- **오탐(false positive)** — 인용문·용어해설·목차·URL·참조부호(예: "도 12", "400번대")·
  이미 태그가 근처(같은 문장·표 헤더·섹션 머리말)에 있는 경우. 오탐은 건수만 요약.
- **판단 보류** — 문맥상 애매한 경우. 사용자에게 질문.

특히 T1은 오탐이 많다. **표 헤더나 섹션 첫 문장에 태그가 선언된 경우 그 표·절 전체가 커버된다**고 본다.

### 3단계 — 보고 형식

```
## tag-audit 결과 — <대상>

**요약**: 실제 위반 N건 (치명 n / 경고 n) · 오탐 N건 제외

| # | 위치 | 규칙 | 문제 | 수정안 |
|---|---|---|---|---|
| 1 | file.md:42 | T2 | "폐수 0% 달성" | "폐수 무배출 [설계목표] — UT-06으로 검증" |

**치명 위반**(있을 경우): 게시 전 반드시 수정할 항목을 먼저 서술.
**오탐 요약**: 용어해설 표 12건, 참조부호 8건 등 — 조치 불필요.
```

수정까지 요청받았다면 Edit로 직접 고치고, 고친 내용을 위 표의 "수정안" 열에 반영해 보고한다.

## 판정 기준 (CLAUDE.md §1 요약)

- 태그는 `[검증값]/[M]`, `[설계목표]/[H]`, `[S]`, `[L]`, `[추가시험]`, `[제외]` 6종.
- **이 프로젝트에 확정된 `[검증값]` 성능 데이터는 없다** — `[M]`이 성능 수치에 붙어 있으면
  근거를 확인하고, 없으면 그것이 가장 심각한 위반이다.
- `[L]` 문헌값을 보증값처럼 서술하는 것도 위반이다.
- 절대치(0%·100%·영구·완전)는 신뢰구간 추정치로 바꾼다.
- 전압 하락을 성능 개선으로 서술하면 **F3 착시** — FE 동반 확인 문구가 없으면 위반.
