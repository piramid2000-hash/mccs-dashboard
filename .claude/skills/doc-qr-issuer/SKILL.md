# 문서 QR 발행 (doc-qr-issuer)

코드: `exec_dashboard/scripts/issue_doc.py` (도면 배포와 **같은** 비밀값·링크·암호화·확인 페이지를 쓴다. 따로 만들지 말 것).

QR 을 찍은 사람은 휴대폰으로 ① 최신 판인지(옛 판이면 빨간 경고) ② 폐기 여부 ③ 핵심값(시험일·로트·결과 등) ④ 받은 파일이 원본과 같은지(SHA-256, 휴대폰 안에서만 계산)를 확인한다.

## 1. 받기 전에 물어볼 것 (모르면 묻고, 지어내지 말 것)

| 항목 | 옵션 | 예 |
|---|---|---|
| 문서종류 | `--type` | 시험성적서, MSDS, 작업표준서, 점검표, 도면 |
| 문서번호 | `--no` | 회사 번호 규칙 그대로 (TR-2026-0142). **없으면 사용자에게 받는다** |
| 제목 | `--title` | HVAC 유닛 성능시험 |
| 판 | `--rev` | 처음 1, 개정 때 올림 |
| 핵심값 | `--fields` | `"시험일=2026-11-20; 로트=L2611-07; 결과=합격"` — 문서에 실제로 적힌 값만 |
| 배포처 | `--to` | 배포처 시트의 키, 쉼표로 |
| 발행자 | `--issuer` | 품질팀 김OO |
| 도장 위치 | `--position` | 우상(기본)·우하·좌상·좌하 — 내용·도면 표제란을 가리면 바꾼다 |

핵심값은 문서에서 읽어 제안하되 **사용자 확인 후** 넣는다 (확인 페이지에 공식 값으로 보이기 때문).

## 2. 발행

```bash
export DOC_SECRET=...        # GitHub Secrets 의 DOC_SECRET 과 같은 값 (16자 이상)
export APP_URL=https://<계정>.github.io/<저장소>/
python exec_dashboard/scripts/issue_doc.py <파일> --type 시험성적서 --no TR-2026-0142 --title "HVAC 유닛 성능시험" \
    --rev 1 --fields "시험일=2026-11-20; 결과=합격" --to 탤런트엘엔지 --issuer "품질팀" \
    --registry "<드라이브 업로드 폴더>/문서등록부.xlsx"
```
- 먼저 `--dry-run` 으로 점검하면 파일·등록부를 쓰지 않는다.
- 마지막 줄 JSON: `mode`(도장/표지), `issued`, `cover`, `verify_url`, `notes`. notes 는 그대로 사용자에게 전달.
- 같은 번호·판이 있으면 멈춘다 → 개정이면 `--rev` 올림, 같은 판 재발행(오타 수정 등)이면 `--force` (등록부 줄을 바꿈).

## 3. 결과 보고 (3~5줄)
1. 만든 파일: 발행본(또는 원본+확인 표지) 경로 — 이 파일을 배포한다 (원본 파일을 따로 돌리지 말 것)
2. 방식: 도장 / 표지(전자서명·암호 PDF 는 서명이 깨지지 않게 원본 그대로 + 표지 한 장)
3. 반영 시점: 등록부·발행본이 드라이브 폴더에 있으면 다음 자동 업데이트(07:05/19:40) 뒤 QR 이 열린다. 급하면 GitHub Actions 'daily' 수동 실행
4. notes (늦은 판 존재, 모르는 배포처 등)

## 4. 안 되는 것 · 주의
- **한글(HWP/HWPX)**: 서버에서 변환이 안 될 수 있다 → 한글에서 [파일 → PDF로 저장하기] 후 그 PDF 로 발행.
- 스캔본(그림만 있는 PDF)도 도장은 찍힌다. 글자 인식(OCR)은 하지 않는다.
- QR 은 24mm, 오류정정 M. 인쇄 축소(2쪽 모아찍기 등)를 하면 읽기 어려우니 원래 크기로 출력.
- 폐기: 등록부 '상태'에 `폐기` → 그 QR 을 찍으면 폐기 경고.
- 공개 저장소다: 발행본·등록부·실제 문서를 **저장소에 커밋하지 말 것**. 드라이브 폴더에만 둔다.
- 비밀값을 바꾸면 이미 찍힌 모든 QR 이 안 열린다. 바꾸지 말 것.
- 이 QR 은 "우리 회사가 발행한 그 판·그 파일"을 확인해 주는 것이지 법적 전자서명이 아니다. 시험기관 성적서의 진위는 발행 기관 조회로 확인한다.
